## Реализация и ownership

- `internal class AndroidImagePreparationPort(files: PlatformFilesPort, inspection: MediaInspectionPort) : ImagePreparationPort`. Текущий старый files contract: createTemporaryFile/source/sink/discard. Pickers и будущий двухфазный destination API не реализовывались.
- `prepareImage` сначала использует injected actual image inspector, затем копирует bytes через Source/Sink с reusable Okio buffer (8192 bytes), <=64MiB. Нет resize/reencode/EXIF removal/orientation rewrite; исходный файл только читается, даже если caller передал TemporaryFile как LocalFile. Повторный actual output inspect предшествует Completed. Source/Sink закрываются на успехе, ошибке открытия второго handle, read/write/close errors и cancellation.
- Factory result принимается в cleanup ownership только после проверки существующего пустого файла. Unexpected nonempty/source alias даёт CONFLICT без перезаписи/discard prior bytes. Files binding обязан создавать уникальный собственный empty temp; adapter не изобретает иной механизм allocation вместо готовящегося parent API.
- `imageFromText` — явная генерация media, не caption UI. Реальные TextPaint/StaticLayout/Canvas/PNG: width1024px, font64px, padding32px, default platform Typeface; wrap и explicit newlines без trim/normalize/shrink/ellipsis. Existing isNativeText проверяет well-formed UTF16/no NUL; text<=4096 UTF16 units, computed layout height+64<=4096px/16MP, цвета строго Long0..0xffffffff, затем Android ARGB Int bit representation. Empty/whitespace являются валидным явным blank media, не молча trim-нутой ошибкой. Overflow возвращает LIMIT_EXCEEDED, не сокращённую картинку.
- Все layout/draw/encode/FS работают в Dispatchers.IO. Cancellation checks стоят между streaming/layout/draw/encoding/inspection/return stages и в bounded writes. Bitmap recycle выполняется в finally. PNG encoding использует bounded sink-backed OutputStream, не whole-image encoded ByteArray; первый write fault сохраняется даже если native encoder возвращает false.
- Completed только после actual output PNG inspection/type/dimensions и последней caller cancellation check. Per-call atomic ownership сохраняется через IO→caller dispatch: недоставленный/late result удаляется, после передачи caller нет suspension/cleanup, способных удалить уже caller-owned temp. Нет глобальной очереди/job/добавленных dependencies. Coroutine cancellation распространяется как CancellationException, structured Cancelled/Failed/UnconfirmedCommit из seam не превращаются в success.
- Discard/recycle best-effort: исключения physical deletion не подменяют primary result и не выходят в CoroutineExceptionHandler. При неудачном OS delete физическое отсутствие temp не обещается; future files binding/recovery остаётся ответственным за cleanup. Уже переданные caller файлы adapter не удаляет.
