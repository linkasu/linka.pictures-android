# Unicode grapheme segmentation

The internal common Kotlin API `graphemeBoundaries(String): IntArray` implements
Unicode **16.0.0** default extended grapheme clusters, UAX #29 rules GB3–GB999
(with start/end boundaries GB1/GB2). `dropLastGrapheme(String): String` removes
one complete final cluster. Offsets are UTF-16 code units, always including zero
and the string length (only zero for an empty string).

The algorithm is independently implemented from the Unicode rules, not copied
from a third-party segmentation implementation. It uses no dependencies,
platform segmentation APIs, regular expressions, network access, or locale data.
Valid surrogate pairs are decoded together. Isolated surrogates remain individual
Other code points: their code units are preserved and normal grapheme rules still
apply (for example a following combining mark joins that Other).

The scan tracks RI parity, Extended_Pictographic/Extend/ZWJ context and Indic
consonant/linker context in constant state, with binary searches of fixed tables.
Time is O(n log R), or O(n) for these pinned tables; output memory is O(n).
There is no backwards context scan. No normalization, locale tailoring, word
segmentation, display-width measurement, or newer Unicode behavior is provided.
Changing Unicode versions is a deliberate data/rule/test update.

Archive collision normalization is a separate internal seam:
`archivePathCollisionKey` removes one directory slash, normalizes NFC using
Java Normalizer on Android/JVM or Foundation on iOS, then applies invariant
Kotlin lowercase in the same order as the Electron peer. This is not full
case folding (`ß` does not equal `ss`) and is not grapheme segmentation or path
validation. Common tests cover decomposed accents, Cyrillic, dotted I, emoji,
file/directory collisions and the valid `UUID..wav` basename. Platform Unicode
normalization versions may differ for newly assigned characters; broader
cross-platform collision fixtures remain part of P05 acceptance, not inferred
from the Unicode16 grapheme conformance result.

## Reproduce and verify

From the repository root, using Python 3 standard library only:

```sh
python3 scripts/generate-grapheme-tables.py
python3 scripts/generate-grapheme-tables.py --check
```

Both commands fetch only the five official sources below into a temporary
directory. For reuse, pass `--cache-dir /absolute/path/to/your/source-cache`.
Cache contents are always verified, never trusted implicitly. No machine-specific
cache paths appear in generated files. `--check` compares exact generated bytes
without writing repository outputs. Network operations require HTTP 200 without
redirect, use a 40-second timeout per source, and read at most 4,000,001 bytes
(rejecting anything above 4,000,000). SHA-256 pins exact bytes; Unicode version
headers are checked independently. A changed upstream license also fails the pin
instead of silently updating licensing terms.

The generator parses and merges sorted adjacent equal-property ranges, rejects
overlaps/out-of-range code points, checks property coverage and known points,
and checks all vector syntax. The generated tables contain 1376 GCB, 78
Extended_Pictographic and 403 InCB ranges. Unlisted code points default to Other,
false and None respectively.

`GraphemeBreakVectors.kt` retains all **1093** official GraphemeBreakTest vectors,
with their original copyright/license header. `GraphemeBoundariesTest` verifies
every boundary and final-cluster deletion for every vector, plus empty input,
malformed UTF-16, non-BMP characters, CRLF, combining marks, emoji ZWJ sequences,
flags, skin tones, Indic conjuncts and long contextual runs.

With JDK 17 and the project's Android SDK configured:

```sh
./gradlew :shared:jvmTest --tests '*GraphemeBoundariesTest'
```
