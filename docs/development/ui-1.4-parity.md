# UI-паритет 1.4: исторический контракт

**Заменён решением пользователя 7 ноября 2026:** действующий визуальный эталон —
[Electron с адаптивным мобильным переносом](electron-ui-parity.md). Ниже сохранена
история прежнего решения и его evidence; она больше не требует оформления1.4.
Согласованные safety/data/accessibility инварианты продолжают действовать.

Решение пользователя, 6 ноября 2026: **«UI 1.4 + согласованные функции»**.
После визуального STOP пользователь 6 ноября явно поручил исполнить весь план
с асинхронными сабагентами (до30). Код возобновлён с visual slice; U1.4 и отдельное
визуальное одобрение пользователя остаются обязательными. Этот контракт обязателен при изменении UI,
навигации, тем, размеров компонентов и при приёмке Android/iOS.

## Цель и приоритет

Повторить внешний вид и привычные сценарии Android **1.4 / code5**, тег `v1.4`,
commit `2073d912f6c70ab0165823f37e4b5704cf72e953`, на обеих платформах.
Это визуальный baseline, не требование вернуть старое хранилище или Android Views.
Источник — проверенные снимки ниже и исходники тега; идентичность магазинному APK
не доказана. Локальная 2.0 и новый development UI не являются эталонами.

Для представления этот контракт выше прежних предложений о редизайне, palettes,
min96dp карточках, min56dp действиях и полноэкранной форме карточки. Полный scope,
[защита](access-policy.md), immutable snapshots, uniform1×1 и storage/format guards
сохраняются. Противоречие с доступностью или безопасностью выносится пользователю
как конкретное минимальное отличие, а не решается самовольным редизайном.

## Обязательное поведение экранов

- **Вход и навигация:** библиотека → доска → назад в библиотеку; создание и
  редактирование идут привычными путями 1.4. Общая фраза не превращается в отдельный
  стартовый технический экран. Возврат/выбор другой доски сохраняет сообщение и
  текущий immutable playback plan по принятому контракту.
- **Библиотека:** сетка плиток занимает экран. Создание, меню доски, rename/delete,
  импорт и настройки остаются на узнаваемых местах. Доступная альтернатива long-press
  использует меню, а не постоянную колонку больших кнопок у каждой доски.
- **Общение:** повторить положение toolbar, фразы, иконок действий, сетки и страниц.
  Пустая/заполненная фраза не раздувает шапку. Обычные «сохранено», «остановлено»,
  «голос доступен» не занимают постоянные строки; актуальная ошибка показывается
  контекстно, важные состояния доступны системной семантике. Speak/Stop и исправление
  доступны без поиска в горизонтально прокручиваемом списке действий.
- **Сетка:** повторить rows/columns, порядок, пропорции изображений, подписи,
  интервалы и полезную площадь на одинаковых данных. Нормализация spans/overflow
  сохраняется как data contract, не оправдывает новую плотность или автосортировку.
  При обычном масштабе не добавлять прокрутку там, где 1.4 помещает сетку целиком.
- **Редактор:** основное пространство — сетка с «+», не длинный список универсальных
  полей и кнопок. Параметры компактны; карточка открывается диалогом поверх сетки.
  SaveCard принимает в draft; сохранение доски явно применяет durable draft.
  Autosave не превращается в автопубликацию и не закрывает форму неожиданно.
- **Оформление:** повторить визуальный характер, цвета, размеры, отступы и иконки
  1.4 по референсам/тегу. Новая типографическая шкала и house components — средства
  реализации, не самостоятельный дизайн. Иконки имеют labels/tooltips/semantics;
  обычные подписи остаются текстом, а не bitmap.

## Согласованные дополнения: где им место

| Дополнение / ограничение | Встраивание без замены основного UI |
|---|---|
| Общая фраза между досками, mixed snapshots, DIRECT/COMPOSE | Та же компактная область фразы и привычные действия; фраза сохраняется между досками и режимами |
| Черновики, autosave/conflict/UNCONFIRMED | Контекстный статус редактора, доступное продолжение через меню/раздел черновиков. Ошибка сохранения остаётся видимой; успех не занимает пол-экрана |
| Import/export/backup/restore/recovery | Входы через меню библиотеки/доски/настройки; отдельный экран preview и конкретное подтверждение, не постоянная панель на доске |
| Защита помощника | Запрос при защищённом действии и управление в настройках. Без пароля общение и открытие досок доступны; постоянного блока unlock/reset над плитками нет |
| Android21/22 OS verification UNAVAILABLE | Объяснение в настройке защиты/попытке недоступного действия, не во всей библиотеке; legacy password unlock и disable с valid capability сохраняются |
| Новая авторизация после системного picker | Явная контекстная re-auth/confirm перед выдачей данных или Resume подготовленной карточки; backend guard не ослабляется ради похожей картинки |
| Доступность, large text, safe area, IME, тёмная/контрастная тема | Та же иерархия, видимый фокус, читаемые labels и платформенные цели касания. В узком окне/крупном тексте необходимое отличие отдельно проверяется и фиксируется |

Новые функции не удаляются ради паритета. Секреты не попадают в backup/скриншоты;
предупреждение об открытом backup и destructive confirmations остаются обязательными.

## Приёмка и порядок продолжения

### Адаптивный срез после решения пользователя 6 ноября

Пользователь явно выбрал адаптивность вместо исключения маленьких устройств.
Android21+/iOS17+, iPhone SE и узкие окна iPad сохраняются. Проверяемый контракт:

| Условие | Представление фразы |
|---|---|
| Обычное окно | Прежняя пропорция фраза/сетка1:4 после фиксированных отступов |
| Короткое окно | Минимум области фразы64dp × max(1, fontScale), чтобы картинка и читаемая подпись не конкурировали за нулевую высоту |
| Два и более элемента | Ширина каждого не больше половины viewport; длинная фраза прокручивается |
| Невозможно вместить два48dp элемента | Прокрутка, а не уменьшение48dp floor или исключение устройства |
| Невысокие миниатюры | Предпочтительная ширина max(96dp, высота), затем cap по viewport; это не minimum96dp основных карточек |
| Крупный текст | Прежний system × portable scale и minimum12sp, необходимые прокрутки; без bitmap/ellipsis/подмены label |

Ни режим общения, ни порядок/снимки сообщения, ни сохранённая сетка, ни настройки
автоматически не меняются. Portrait двух первых миниатюр проверен оригинальными
Android21/iPhone PNG. Short-landscape параметры проверяются отдельным native
срезом: approval всего U1.4 и physical/AAC из него не выводятся.

**Визуальный срез принят пользователем** после просмотра текущих iPhone portrait/
landscape и Android landscape кадров: ответ «Принимаю срез». Исходный UI commit
`6ae5a47`, preferred width96dp/half-viewport cap/min-height64dp. Это одобрение
геометрии доски и фразы, не всех экранов или accessibility matrix. Production/
migration admission, physical/AAC и публикация этим ответом не разрешены.

### Следующий проверочный срез: настройки и крупный текст

Только выделенная synthetic development-библиотека. Сначала read-only UI
показывает фактические исходные scale/contrast и системные роли переключателей.
Затем проверяется portable scale2.0 + high contrast с обычной ручной кнопкой
сохранения, без обхода запрошенной приложением авторизации; язык и параметры досок
не изменяются. В непрерывном foreground без установленной защиты приложение
может сохранить сразу: тест не требует искусственного дополнительного prompt.
Обязательная fresh authorization после внешнего picker этим не ослабляется.
После кадров/доступности карточек исходные значения возвращаются тем же явным UI
путём и перечитываются. Это не замена проверки system × portable fontScale.

Нельзя сохранять повторно по таймауту, обходить conflict/UNCONFIRMED или сбрасывать
настройки. При неоднозначном исходе фиксируются последний наблюдаемый этап и
возможные оставшиеся значения; библиотека/сообщение/черновики не очищаются и не
переимпортируются. Общение должно работать и при недоступных локальных голосах.
Пока эти шаги не выполнены и не просмотрены, font/contrast gate остаётся OPEN.

7 ноября пользователь выбрал **«Прокрутка (Recommended)»** после просмотра
реальных iPhone2.0 кадров начала и окончания текста. Принята стратегия: полные
подписи читаются внутри карточки, картинка сохраняется; структура доски и
обычная1.0 геометрия не меняются. Это не approval всей font/contrast матрицы.
Native2.0/contrast/save/read/scroll/restore проверены на iPhone17, iPad17 и Android21;
системный fontScale не изменялся. iOS-проверка дополнительно подтверждает отсутствие
изменения фразы и audio state от жестов. TalkBack/VoiceOver/physical остаются OPEN.

Дополнительно на iPad17 проверен настоящий system Dynamic Type: large → максимум
accessibility-extra-extra-extra-large → large, без изменения portable1.0.
Девять карточек доступны; отдельные жесты раскрыли конец длинной подписи, картинка
и фраза/audio state сохранились. System category и обычная cold geometry возвращены.
Это частичная system-scale проверка, не вся матрица system × portable и не iPhone
system maximum; исходные кадры и точные границы — в Settings evidence.

**Полный U1.4 сейчас OPEN; приняты только описанные выше срезы.** Пользователь
поручил продолжать до готовности к выпуску; отдельная команда для каждого
симуляторного сценария не требуется. Оставшийся порядок:

1. Зафиксировать одинаковый синтетический набор и состояние для пары 1.4/новая:
   библиотека, «ХОЧУ» 3×3, пустая и заполненная фраза, многостраничная доска,
   редактор с карточкой и модальная форма. Личные данные не использовать.
2. Сначала показать заполненную доску рядом с 1.4. Снимать один viewport/ориентацию/
   системный fontScale; iOS сравнивать при сопоставимом content area с учётом safe
   area. Записать build/commit (для WIP также diff identity), OS, dp/pt и pixels,
   fixture/state, путь получения. Просмотреть PNG, не принимать только XML/compile.
3. Сравнить блоки и положения действий, число видимых строк/колонок, отступы,
   размеры/цвета/иконки, долю площади сетки, поведение Back/выбора/сохранения.
   Overlay/diff помогает найти различия; не выдавать различия шрифтового rasterizer
   и OS chrome за нарушение. Каждое продуктовое отличие — причина и решение
   пользователя; порог «достаточно похоже» агент сам не придумывает.
4. Получить визуальное подтверждение пользователя для доски, затем пройти остальные
   строки атласа на Android phone/tablet и iPhone/iPad, portrait/landscape. Отдельно
   large text/контраст/IME/keyboard/TalkBack/VoiceOver и agreed new flows.
5. U1.4 закрыт только при принятых парах и сценариях обеих платформ с журналом
   исключений. Затем продолжать оставшуюся интеграцию и safety/release gates;
   прохождение U1.4 само по себе их не закрывает.

Новые [empty-startup PNG](../progress-screenshots/2026-11-05-product-r2/) — диагностика
запуска, **не визуальное одобрение**. Новый library UI с защитой и колонкой кнопок
отклонён как направление. Unit/Native PASS не доказывают UI-паритет.
