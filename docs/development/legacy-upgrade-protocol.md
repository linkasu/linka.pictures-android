# P09: cross-store admission protocol — accepted implementation contract

COORD, 5 ноября 2026. Conditional implementation только на isolated synthetic data; **G4 не PASS**, normal `su.linka.pictures` на настоящие данные не устанавливается. Исходники legacy не меняются, downgrade1.4 не rollback.

## Writers и граница активации

Legacy SetsManager/importer/editor/assets loader/Cookie/default preferences выключены startup selector до inventory; иной app process/extension writer отсутствует. Только один coordinator на app-private root. Новые writers: staging StorageRuntime/schema1, отдельный CredentialStore и небольшой admission journal. Это не общая SQL-транзакция.

Новая библиотека строится в уникальном owned generation root под `filesDir/pokazhi-v1/libraries/<migrationId>` на той же FS. До активации её не видит normal UI. `filesDir/sets` и прежние prefs остаются без записи/удаления. Secret record — отдельно в noBackup root, вне новой библиотеки/backup. После успешной активации startup читает только действующий новый record; legacy password не переимпортируется после изменения/disable/reset.

Один bounded journal хранит schema, migrationId, SHA256 source inventory+несекретных настроек, phase/counts; **без password/verifier/tokens/URI/абсолютных путей**. BoardIds для source entries выводятся из migrationId+порядкового номера стабильного sorted inventory, не из case-folded имени. Никакой склейки по content hash/названию.

FSM: INVENTORY → COPYING_VALIDATING → ACCESS_READY → READY_TO_PUBLISH → COMMITTED. BLOCKED/FAILED/CANCELLED/UNCONFIRMED отдельны; persisted unknown outcome не автоматически повторяется. Unknown journal schema/непринадлежащие каталоги/смешанный state — fail closed, не cleanup/fallback.

## Порядок

1. До source SQLite/изменений открыть существующий bounded `active` receipt. Он содержит только подтверждённый migrationId/counts/source fingerprint и признак обязательного initialized credential record. При корректном active root открыть его обычным StorageRuntime schema admission и потребовать существующий валидный CredentialRecord, даже если он теперь enabled=false. Отсутствующий record на известном active root не превращается в Unprotected. Никакого reimport/source reset при этом пути.
2. Если active нет, inventory всех обычных файлов legacy sets; canonical containment/no symlinks; sorted case-sensitive filename identity, actual sizes/hashes. Файлы/каталоги неподдержанного типа, нестабильные source/prefs, нехватка места или источник сверх2GiB дают BLOCKED с исходником нетронутым. Не активировать неполный отчёт как полную библиотеку. Коррупция обычного файла <=2GiB — retained, не blocker остальных.
3. Создать journal+owned generation mustCreate. После interrupted stage без active receipt требуется явное Resume; source fingerprint должен совпасть. Reopen staging runtime авторитетно определяет, какие стабильные BoardIds уже published, затем продолжить отсутствующие entries. Несомненный уже committed entry не импортировать заново.
4. Копировать каждый source потоково в зарегистрированный own native TemporaryFile; real LINKA limits500MiB/image-audio64MiB/inspection остаются. Успешный decode публикует board с закреплённым BoardId в staging library. Неподдержанный/повреждённый файл сохраняет exact original bytes через ARCHIVE media/RetainedArchive<=2GiB и видимый reason. Нет partial board publication. Leases закрываются после writer refs; Source закрывается потребителем; staging failure не трогает source.
5. Исторический standard flat1.3 (включая built-in «Болит») читается **только отдельным internal migration entry** существующего LinkaCodec/LinkaWire с тем же bounded parser/active-feature/media validation. Обычный внешний `read` whitelist1.0/1.2/2.0/3.0 не расширяется. Fixture1.3 + unknown2.99 доказывают эту границу; встроенные assets брать по APK/Git blobs, не делать вывод «их6» из case-insensitive checkout.
6. Настройки source `GridSettings.fromInt`: isOutput=true только1/3 → board.behavior.defaultMode=COMPOSE, остальные значения→DIRECT; isPagesButtons=true только2/3 → BoardPresentation.showPageButtons. Источник — actual per-filename prefs/default3, не игнорировавшийся1.4 raw directSet. withoutSpace → существующий inputStyle. Значение global message mode после начала новой работы не переключается скрытно при каждой доске: сохранённые board defaults остаются defaults. Прежние showOutput semantics не теряются в неизвестном поле. Не добавлять поле в PortableSettings ради уже выражаемого mapping.
7. До activation выполнить idempotent import legacy credentials: если parent=false — initialized disabled record; если true — exact stored String (missing/null→empty), legacy=true и штатный versioned KDF. Stored value не trim; input-only legacy trim сохранён. Empty/space-edge/Unicode states не отключают lock;21/22 безOSreset остаются защищены. Existing stage record допускается только если валидно соответствует исходному legacy состоянию; неизвестный/modern/conflicting record не overwrite. Secret нет в journal/library/recovery report, raw prefs не копировать в новый plaintext backup. Unknown credential publish блокирует activation до explicit reopen.
8. Проверить завершённость staging entries/settings/media и повторно стабильность source fingerprint. Закрыть staging runtime, подготовить READY_TO_PUBLISH receipt и atomic publish `active` на той же FS. Последний guard проверяет живой migration admission, не UI boolean. При исключении rename одна independent exact old/new readback: new доказан→Completed; old доказан→Failed/Cancelled; иначе UnconfirmedCommit/BLOCKED. Исходная библиотека остаётся нетронутой во всех случаях.
9. После authoritative active receipt открыть новый runtime; journal COMMITTED/progress — вспомогательны, не более сильный commit marker. Crash после activation до progress update не вызывает reimport. Source/recovery не удалять автоматически, прежние архивы после новой работы не называть актуальным rollback.

## Обязательные проверки до root binding

Новая установка/пустой источник; несколько custom boards, duplicate/case names и7Git assets;1.3/unknown version; corrupt среди хороших; parent enabled/disabled/missing/empty/space/Unicode; per-filename settings0..3+invalid. Stage/source/credential sentinel hashes проверяются до/после.

Fault/termination до/после каждого journal write, archive prepare/publication, settings save, credential write, active rename и postcommit progress. Reopen читает новый state независимо, никакого доказательства по незакоммиченному staging writer. Поздний cancel не отменяет подтверждённый activation; unknown исход не называется Failed/пустой библиотекой. Повтор startup после последующих пользовательских изменений не обновляет данные/пароль из legacy.

Это протокол для новой реализации; само наличие документа не доказывает persisted-state атомарность, runtime миграцию, подпись или G4.
